# CHECKLIST — Estándar "LISTO PARA PORTFOLIO"

Un repositorio no se marca como terminado hasta cumplir esto:

## Código
- [ ] Sin código muerto ni comentado
- [ ] Naming consistente y descriptivo
- [ ] Sin duplicación evidente
- [ ] Manejo de errores donde corresponde
- [ ] Sin credenciales/secrets hardcodeados

## Git
- [ ] `.gitignore` correcto (sin `venv/`, `node_modules/`, `.env`, `db.sqlite3`, `__pycache__/`)
- [ ] Sin secrets en el historial (no solo en el HEAD)
- [ ] Commits con mensajes claros
- [ ] Sin archivos gigantes o basura versionada

## README
- [ ] Qué problema resuelve
- [ ] Para quién está pensado
- [ ] Funcionalidades principales
- [ ] Tecnologías usadas
- [ ] Instalación y configuración (variables de entorno incluidas)
- [ ] Cómo ejecutar
- [ ] Screenshots o demo
- [ ] Usuario/contraseña de prueba si aplica (credenciales seguras, no reales)
- [ ] Estructura del proyecto si aporta claridad
- [ ] Mejoras futuras (opcional pero suma)

## Presentación visual
- [ ] Screenshots de calidad (pantalla principal + funcionalidades clave)
- [ ] Responsive mostrado si aplica
- [ ] GIF/video corto si aporta valor

## Demo
- [ ] Demo online si es técnicamente viable, priorizada sobre "clonar y configurar"

## Seguridad
- [ ] Sin datos reales de personas/pacientes
- [ ] Sin API keys ni tokens

## Puntaje (0-100)
- Código: /25
- Arquitectura: /15
- README/documentación: /15
- UI/UX: /10
- Git/historial: /10
- Testing: /10
- Deploy/demo: /5
- Seguridad/configuración: /5
- Presentación visual: /5

Solo se marca "LISTO PARA PORTFOLIO" cuando el repositorio refleja honestamente el estándar,
no cuando "ya no da vergüenza".
